# CNS方法融合：保留、改造、舍弃

CNS以nature-research和da-diao-cha为科学骨架，选择ARIS阶段链的具体优点。来源技能均为当前本地版本；MANIFEST记录源身份。这是方法融合，不覆盖上游ARIS，不移植其全部脚本、模型调用或默认预算。

| 来源 | 保留 | CNS中的改造 |
|---|---|---|
| nature-research（本地） | 重要问题、可迁移机制、建设与攻击、完整物理成本、非拟合预测 | 长线首要标准，允许近期专业成果；不是发表保证 |
| da-diao-cha（本地） | 先例攻击、竞争解释、重推导、失败上限与投入决策 | 按战略触发条件进入，不每轮全盘审查 |
| research-progress-workflow（本地） | 探索/验证/硬件分层、批量工程闭合、避免审批循环 | 工程修复之后立即做下一科学判别，原合同不变 |
| idea-discovery（ARIS链） | 文献→候选→查新→凝练，自动选择、可恢复阶段 | 通常少量候选、一条主线；移除默认8 GPU小时/三路pilot/机械阶段门槛 |
| research-refine（ARIS链） | 问题锚点、最小充分方法、一项主贡献 | 不迭代到9分；以问题和判别可执行性结束凝练 |
| novelty-check（ARIS链） | 从主张检索，分清邻近与实质重复 | 查光学/物理/控制及跨领域的一手全文；不限定ML会议；有效数学包含也能否定创新，不凭摘要确认首次 |
| formula-derivation（已有方法） | 固定对象、公式链、假设、恒等式/命题/近似/解释 | 对接实际波前服务与资源；模型简化不能替代主对象 |
| experiment-plan（ARIS链） | 主张→证据→运行顺序，强基线及简单性检查 | 判别优先、单位与总成本、独立测试；不强制三种子和大消融矩阵 |
| experiment-bridge（ARIS链） | 从计划实施、复用现有代码、合同与实现相连 | 用原项目目录/权限/消费账；不自动clone、训练或启用watchdog |
| analyze-results（ARIS链） | 观察→解释→意义→下一实验 | 补充误差传播、零分母处理、真实独立单位与资源反转，不把seed均值作为通用理论验证 |
| result-to-claim（ARIS链） | 实验之后限定主张，补证/改向/确认 | 实际结果身份不等于主张成立；不固定昂贵复审或把同系列评审当独立实验 |
| experiment-audit（ARIS链） | 真值、归一化、死代码、结果存在与范围检查 | 关键完整性FAIL不能支撑相应主张；不继承“永不阻塞且仍写positive”的做法 |
| kill-argument（ARIS链） | 最强拒稿论证、逐点回应及未解决关键项 | 把攻击转换成证据义务；默认同回合攻防，不强制两个ultra代理，不按批评条数裁决 |
| auto-review-loop（ARIS链） | 修复—复核—保存问题账 | 仅在新证据或具体决策下复审；不用评分正反馈无限循环，不造通过 |
| research-pipeline（ARIS链） | 端到端阶段继承、可恢复状态、写作分支 | 从当前阶段进入，沿既有goal/真实调度；不新建重复状态/模型轮询；明确长期研究与单假说收口 |

## 不继承的默认行为

固定高档模型与高推理、自动模型瀑布、为正评分反复投票、将ML年份/会议白名单当光学查新、技能默认资源作为执行许可、自动终止不属于自己的任务、摘要新颖性裁决、忽略完整性FAIL、缺模板脚本就阻断可做的科学推导、每次开新窗口/全链重跑、未授权训练/硬件/通知。

## 一次科学回合的实际问法

问题：这项代价来自物理必要性、可观测信息不足还是算法实现？
推导：从实际服务量出发，在明确量词和合法域中能证明什么？
构造：什么最小合法动作能产生与强经典解释不同的预测？
判别：哪个正/负/反转结果会改变下一选择？
收口：当前最窄主张、未证事项及条件旗舰上限是什么？

进入大审查时，在这些问题之上重审问题的重要性和方向选择，不只审代码是否运行。完成工程修复后回到主线；没有新机制时保留负结果，不靠改名、阈值、假想硬件或更弱基线救场。
